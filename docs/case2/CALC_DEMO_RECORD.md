## 1. 这个案例做了什么

三个独立成员分别实现一个算术函数，通过 Team Hub 告知其他成员调用方法，再调用另一位成员的函数完成自己的组合计算。

- Alice 实现加法，并使用 Bob 的减法计算 `(8-3)+2`。
- Bob 实现减法，并使用 Carol 的乘法计算 `(4×3)-5`。
- Carol 实现乘法，并使用 Alice 的加法计算 `(2+3)×4`。

这是一个最小协作验证：独立交付、实际消息交接、复用另一成员的代码、执行验证。它不证明复杂业务协调、自动唤醒或文件冲突防护已经可靠。

## 2. 实际成果

三个成员使用同一个项目目录：

```text
F:\System\Desktop\学习\OOAD\case1
├─ add.mjs
├─ subtract.mjs
└─ multiply.mjs
```

文件内容分别为：

```javascript
// add.mjs — Alice
export function add(a, b) {
  return a + b;
}
```

```javascript
// subtract.mjs — Bob
export function subtract(a, b) {
  return a - b;
}
```

```javascript
// multiply.mjs — Carol
export function multiply(a, b) {
  return a * b;
}
```

没有网页、后端服务、数据库或第三方依赖。组合计算通过 Node.js 临时命令执行，没有额外创建测试文件。

1. 核对消息收件人为本案例成员，写入文件符合分工，命令只是本地验证，再批准操作。

## 6. 本次遇到的问题与展示边界

- Alice 途中出现过 `Turn time budget reached`，后续执行成功，不能描述为全程无故障。
- Bob、Carol 曾执行用于等待的 `setTimeout` 命令，其中有进程超时。复演提示词已明确禁止用睡眠命令等消息。

- 该案例共享文件夹，通信传递的是函数调用说明与结果，并非隔离机器之间的代码文件传输。
- 使用指定文件分工，未验证多成员同时修改同一文件的冲突处理。
