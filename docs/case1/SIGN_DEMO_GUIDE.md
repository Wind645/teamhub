# case1：宿舍门口留言牌——三 Agent 最小演示流程

本案例用于 pre 展示。目标是只生成 **一个 `index.html` 文件**，双击就能打开网页。本文件记录任务和操作流程，不表示网页已生成或验收完成。

## 1. 三个用户各有什么要求

- **Alice 代表早睡的同学：**留言牌要写“晚上 23:00 后请保持安静”。
- **Bob 代表负责收快递的同学：**留言牌要写“快递请放门口置物架”。
- **Carol 代表注重隐私的同学：**留言牌不能出现姓名、手机号和个人作息明细。通用安静时段可以公开。

Alice 和 Carol 只通信、不写文件；Bob 收集要求、取得隐私检查结论后，负责生成 HTML。这里的 Alice、Bob、Carol 是助手身份，不应作为住户姓名展示到留言牌上。

## 2. 准备一个新的空文件夹

例如在文件资源管理器中新建：

```text
C:\Users\LENOVO\teamhub-lab\door-sign-demo
```

如果这个目录已有旧成果，另建一个空目录。三个助手窗口都新建对话，并选择**同一个空文件夹**。使用已能正常回复的模型和 Team Hub 连接。

下面代码框中的内容是**发给对应助手的聊天任务**，不输入 PowerShell。先发 Alice、Carol，再发 Bob。

## 3. 发给 Alice

```text
本次案例 SIGN-01。你代表我的住宿需求：门口留言牌必须写“晚上23:00后请保持安静”。

请通过 Team Hub 把这条要求发给 bob，并请 carol 检查是否涉及隐私。收到具体异议时再协调，否则不要重复确认。不写文件，不创建子代理，不处理旧案例。
```

## 4. 发给 Carol

```text
本次案例 SIGN-01。你代表我的隐私需求：门口留言牌不能出现姓名、手机号或个人作息明细；通用的安静时段可以公开。

请通过 Team Hub 将这条规则发给 alice 和 bob。收到拟展示的文字后检查一次，把结论回复 bob。不写文件，不创建子代理，不处理旧案例。
```

## 5. 发给 Bob

```text
本次案例 SIGN-01。我要做一张宿舍门口留言牌，必须包含“快递请放门口置物架”。

请通过 Team Hub 收集 alice 的住宿要求和 carol 的隐私规则，整理最终文字并发给 carol 检查。收到检查结论后，创建唯一文件 index.html：文字大、清楚、美观，CSS写在HTML内，不使用外部资源。

只做静态留言牌，不加按钮、后端、数据库或依赖，不创建子代理。缺消息时说明等待哪一方并结束本轮，不无限轮询。完成后通知 alice 和 carol。
```

如果重新排练且旧消息可能混入，把三份任务及后续“继续”中的 `SIGN-01` 统一改成一个新编号，例如 `SIGN-02`。

## 6. 等消息时怎么操作

1. 核对并批准任务范围内的消息发送、读取和 Bob 创建 `index.html` 的操作（如界面要求审批）。
2. Bob 收到 Alice 的需求和 Carol 的规则后，整理拟展示文字，发给 Carol 检查。
3. Carol 如果停在等待状态，确认 Bob 已发送成功后，在 Carol 输入：

   ```text
   继续 SIGN-01，处理新消息，完成本次任务。
   ```

4. Carol 回复检查结论后，如果 Bob 已结束这一轮，再把同一句“继续”发给 Bob，让他读取反馈并生成网页。
5. 其他成员若仍在等消息，也只在新消息确实已发送后推动下一轮。不要在运行中反复追加任务，也不要用睡眠命令或无限轮询等待。

以实际工具调用和消息结果为准。助手说“已发出”但没有发送成功记录，不算验证了通信。

## 7. 打开网页并验收

Bob 完成后，在共同选择的项目文件夹里找到 `index.html`，双击用浏览器打开。它应是一张大字、清楚、美观的静态留言牌，样式写在 HTML 内。

**最终业务验收只有三项：**

1. 有“23:00 后保持安静”的要求。
2. 有“快递放置物架”的要求。
3. 没有姓名、手机号或个人作息明细。

同时核对产物仍只有一个 HTML 文件，没有额外引入后台服务、数据库或外部资源。若网页不符合要求，将具体问题反馈给 Bob；涉及隐私的文字修改再由 Carol 检查。

## 8. pre 展示什么

按下面顺序展示即可：

1. Alice 发给 Bob 的安静时段需求消息。
2. Carol 发给 Bob 的隐私规则消息。
3. Carol 对 Bob 拟展示文字的检查反馈。
4. 双击打开的最终网页，指出两条提示文字及隐私规则均得到满足。

Bob 自己的快递要求可在他的原始任务中看到。只需要这些真实记录和网页，不需要展示整个开发过程。

讲解可以这样说：

> 三位用户分别提出住宿、快递和隐私要求。Alice 和 Carol 通过 Team Hub 将要求传给 Bob，Bob 汇总文字并请 Carol 检查，最后生成一张可以直接打开的留言牌。这个案例展示最基础的多用户需求汇合与通信。

如果中间由操作者手动输入“继续”，如实说明。这不证明空闲助手可以自动唤醒，也不承担复杂项目开发的展示目标。
