# case3：宿舍一周值日表——三 Agent 协商演示

本文件是待执行的操作流程。本次只整理文档，没有生成网页或验证实际通信结果。

## 1. 做什么，做到哪里结束

做一个静态网页，显示周一到周日三位室友的值日安排。每人每周只负责一次自己的任务；没有任务的日期显示“无安排”。

- Alice 代表小林：扫地，只能周二或周四；不与倒垃圾安排在同一天。
- Bob 代表小周：倒垃圾，只能周二或周三。
- Carol 代表小陈：擦桌子，只能周三或周四，而且必须安排在扫地之后的日期。

本案例把“不与倒垃圾同一天”作为验收要求；“之后”指本周更晚的一天，不是同一天晚些时候。三个名字都是演示用虚构名字。

三个 Agent 通过 Team Hub 交换各自要求，协商安排，再分别写自己的结果。Bob 额外维护汇总页面，但不能替别人放宽要求。

最终只有四个文件：

```text
duty-demo/
├─ index.html    Bob：公共展示页面，CSS 写在 HTML 内
├─ alice.js      Alice：小林的安排
├─ bob.js        Bob：小周的安排
└─ carol.js      Carol：小陈的安排
```

不做后端、数据库、依赖安装、登录、历史记录或第二轮需求。双击 HTML 展示成功，保留通信证据后就结束。

## 2. 准备三个窗口

1. 在文件资源管理器新建一个空文件夹，例如 `C:\Users\LENOVO\teamhub-lab\duty-demo-small`。如果已存在且有旧成果，请换一个新文件夹。
2. Alice、Bob、Carol 各自新建对话，三个窗口选择同一个新文件夹。不要选择 Team Hub 源码目录或 `docs/case3`。
3. 使用已能正常工作的模型和 Team Hub 连接。
4. 按下面顺序给 Alice、Carol、Bob 发送任务。不必等待前一个完成才给下一个发送。

下面代码框是聊天任务，不是 PowerShell 命令。只复制对应任务，不要把整份文档发给 Agent，以免提前暴露参考安排。

为了减少无关的接口讨论，三份任务统一使用一个简单格式：各自的 JS 文件设置 `window.dutyAlice`、`window.dutyBob`、`window.dutyCarol`，对象字段为 `name`、`task`、`day`；`day` 用 1～7 表示周一到周日。日期仍由三个 Agent 实际协商。

## 3. 发给 Alice

```text
本次案例 DUTY-SMALL-01。你是 alice，代表室友小林。我们要做一个“宿舍一周值日表”静态网页。

我的要求：我负责扫地，每周一次，只能周二或周四。扫地不要与倒垃圾安排在同一天；本次请把这个条件作为必须满足的要求。

请通过 Team Hub 把我的要求发给 bob 和 carol，并了解他们各自的时间要求。bob 会汇总候选安排，请检查候选是否满足我的条件，回复一次明确的同意或具体异议。不能为了结束协商而放宽我的要求。

确认最终安排后，只创建 alice.js，设置 window.dutyAlice = { name: "小林", task: "扫地", day: 协商确定的星期数字 }。day 用 1～7 表示周一到周日。不要提前猜测最终日期。写好后通过 Team Hub 通知 bob 文件和结果。

只修改 alice.js，不改其他人的文件，不创建子代理，不处理旧案例，不增加任何功能。消息带 DUTY-SMALL-01。不编造对方回复；没有新信息时不反复确认，不无限轮询。缺消息就说明等谁、缺什么，并结束本轮。
```

请通过 Team Hub 把我的要求发给 alice 和 bob，并了解他们各自的时间要求。bob 会汇总候选安排，请检查候选是否满足我的条件，回复一次明确的同意或具体异议。不能为了结束协商而放宽我的要求。

确认最终安排后，只创建 carol.js，设置 window.dutyCarol = { name: "小陈", task: "擦桌子", day: 协商确定的星期数字 }。day 用 1～7 表示周一到周日。不要提前猜测最终日期。写好后通过 Team Hub 通知 bob 文件和结果。

只修改 carol.js，不改其他人的文件，不创建子代理，不处理旧案例，不增加任何功能。消息带 DUTY-SMALL-01。不编造对方回复；没有新信息时不反复确认，不无限轮询。缺消息就说明等谁、缺什么，并结束本轮。

## 5. 发给 Bob

```text
本次案例 DUTY-SMALL-01。你是 bob，代表室友小周。我们要做一个“宿舍一周值日表”静态网页。

我的要求：我负责倒垃圾，每周一次，只能周二或周三。

请通过 Team Hub 把我的要求发给 alice 和 carol，收集他们各自的时间要求。收齐后提出满足所有要求的完整候选安排，发给两人核对。你负责汇总，不替他们改变要求。收到两人对同一版本安排的明确同意后，通知双方安排已确认；若有具体异议，只针对异议修改并重新核对。

你只维护 bob.js 和 index.html：
1. bob.js 设置 window.dutyBob = { name: "小周", task: "倒垃圾", day: 协商确定的星期数字 }，day 用 1～7 表示周一到周日。
2. alice.js 和 carol.js 由他们各自创建，分别设置 window.dutyAlice 和 window.dutyCarol，字段同样为 name、task、day。不要代写或修改这两个文件。
3. index.html 显示周一至周日的值日表，清楚展示任务和负责人，没有任务的日期显示“无安排”。CSS 写在 HTML 内。
4. 用普通 script 标签依次加载同目录 alice.js、bob.js、carol.js，再执行汇总渲染。不要使用 type="module"、import、fetch、外部资源或依赖，确保双击 HTML 就能展示。页面从三份数据读取结果，不把日期写死在 HTML 中。
5. 等待回复期间可以先写页面骨架；数据未齐时显示“等待安排”，不伪造数据或宣称完成。三份数据齐全后检查展示逻辑和约束，报告实际检查结果，并通知两人完成。

最终项目只有 index.html、alice.js、bob.js、carol.js 四个文件。不做后端、数据库、按钮、登录、历史记录或第二轮需求，不创建子代理，不处理旧案例。
消息带 DUTY-SMALL-01。不编造对方回复；相同安排确认一次即可，不循环互相确认、不无限轮询。缺消息就说明等谁、缺什么，并结束本轮。
```

## 6. 运行中如何推动

你要观察的顺序是：三方发送要求 → Bob 提出候选 → Alice、Carol 各回复一次 → Bob 通知确认 → 三方各写自己的文件 → Bob 汇总检查。

若界面要求审批，核对是本案例的消息收发或分工内文件操作后再允许。

某个助手已经结束本轮、正在等待，而另一方刚发来了消息，就给等待方发送：

```text
继续 DUTY-SMALL-01。处理新收到的 Team Hub 消息，完成本次尚未完成的工作。已经确认且没有变化的内容不要重复确认；若仍缺信息，明确说等谁、缺什么。
```

例如 Bob 发出候选后，推动 Alice 和 Carol；两人回复后，再推动 Bob。Bob 通知最终安排后，推动尚未生成文件的成员。

不要在助手仍运行时连续追加“继续”。有人工推动就如实记录，不能把它展示成全程自动唤醒。

如果三人反复说“等确认”，先查看实际消息：针对同一版本已有明确同意时，不需要再对“收到同意”进行确认。若候选已改变，则需重新核对改变后的安排。

重新排练时，把三份任务和后续“继续”中的编号统一改成 `DUTY-SMALL-02` 等新编号，避免旧消息混入。

## 7. 打开网页并验收（仅操作者看）

三个成员交付后，在共同项目文件夹里确认只有四个文件，双击 `index.html`，用浏览器打开。

逐项检查：

- 网页显示周一到周日，三项任务各出现一次，负责人正确。
- 扫地在周二或周四；倒垃圾在周二或周三；擦桌子在周三或周四。
- 扫地与倒垃圾不同一天，擦桌子严格晚于扫地。
- 页面显示与三个 JS 文件一致；刷新后仍能展示。
- 有真实 Team Hub 需求消息、候选安排和确认结果。只看最终网页不能证明发生过通信。

**参考可行安排：周二小林扫地，周三小周倒垃圾，周四小陈擦桌子。**

在上述条件下，扫地若排周四，擦桌子就没有更晚的可用日期，因此扫地只能周二；倒垃圾随之只能周三，擦桌子只能周四。这段仅用于验收，不要提前发给 Agent。

若页面空白或一直显示等待，先确认四个文件在同一目录、文件名正确且三份安排都已写入；把具体问题交给负责文件的成员处理。不要为了打开页面再安装依赖或增加服务器。

这个案例展示的是多用户独立需求的协调与通信。参考答案由操作者验收使用；最终成果、消息和人工推动步骤都以实际记录为准。做到这里就结束。
